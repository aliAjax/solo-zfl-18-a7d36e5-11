# 桌游规则迁移中心

一个纯前端本地应用，在原有「桌游规则遗忘点卡片库」基础上扩展为**跨桌游规则迁移中心**。数据全部保存在浏览器 localStorage，直接打开 `index.html` 即可使用，也可在本目录启动静态服务访问。

## 卡片库（原功能保持可用）

- 桌游收藏的新增、删除、搜索、按人数/复杂度筛选、按未玩天数/名称/复杂度排序。
- 每张规则是带独立 id 的卡片，分四类：容易忘的规则、常见争议、开局准备、计分提醒。
- 卡片可关联引用其它卡片（点击引用可跳转高亮），并防止形成循环引用。
- 「标记今天玩过」、封面图、本地保存与刷新恢复均保留。

## 迁移中心

- **新建迁移批次**：选择源桌游、目标桌游与每张卡的适用人数，可勾选任意源卡。
- **四项问题检测**：
  - 重复：目标已有同内容卡，或批次内将产生重复卡；
  - 缺失：源卡已删除（原文仍保留在批次里）；
  - 冲突：适用人数超出目标桌游人数范围；
  - 循环引用 / 失效引用：在「迁移后的目标图」上检测。
- **逐项处理**：每项都保留不可改的原文，可改编迁移文本、改分区/人数、作为新卡迁入、沿用现有卡、显式覆盖现有卡、跳过。严重问题阻断发布。
- **批次生命周期**：草稿 → 发布 → 回滚。发布是原子提交，失败不改原数据；已发布卡不会被静默覆盖（覆盖需显式选择并记录原文快照）；重复提交幂等，不生成重复卡；回滚删除本批新建卡、恢复被覆盖卡原文，且可安全重复执行。

### 双标签页并发

两个标签页同时修改同一批次/桌游时，系统用版本号 + 随机 nonce 做乐观锁与确定性仲裁，通过三方合并**保留双方版本**（进入待合并队列，不互相覆盖）。横幅提示后可打开差异比较视图：字符级增删高亮，逐字段/逐迁移项选择保留哪一侧，也可一键全取某侧，确认后才合并；合并前任何一侧都不会丢失。

### 导入 / 导出

- 一键导出全部 JSON；支持整库替换与按 id 合并两种导入模式。
- 导入前整批校验：失效引用、卡/桌游 id 重复、重复卡、人数越界、非法批次状态/动作/分区、自引用与循环引用、坏 JSON。
- 任一问题都**整批拒绝，原数据不变**，并列出全部问题位置。兼容旧版字符串数组数据（自动升级为卡片模型）。

## 文件结构

- `index.html`：卡片库 / 迁移中心两个标签页。
- `storage.js`：数据模型、旧数据迁移、版本/nonce、跨标签页三方合并、原子提交。
- `migration.js`：批次、问题检测、发布/回滚、导入导出校验（纯逻辑）。
- `migration-ui.js`：迁移中心界面与分叉合并视图。
- `app.js`：卡片库界面。
